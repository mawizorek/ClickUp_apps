How it works

Each render boots sql.js in the browser, loads schema.sql + seed.sql from maw-prose, and draws one FileMaker layout. Two contracts constrain every render:

  • Data: schema.sql (generated from the DDR). No invented fields.
  • Visual: object library families + theme vectors. No ad-hoc styling.

schema.sql tracks the DDR via fmp-state. New DDR drop → STATE.md updates → diff against schema.sql → stale renders surface as broken queries.
