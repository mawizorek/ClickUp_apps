# App Ledger — THE single source of truth for every app

**One file. One row per app. Every folder in the repo root appears here or in the not-apps line.** `brain-config/app-index.md` is retired to a stub; there is no second index.

**Also the tiebreaker against stale reads and CDN lag.** When your read disagrees with this file, **re-read at HEAD and reconcile** — the gate cuts both ways (below).

## 📏 Size (target **~16KB**, ceiling **22KB** — LOCKED 2026-07-26, Michael)

**Each row is CURRENT STATE, not version history.** Per-version narrative lives in git history + the PR description + that app's own `README.md`/`next-build-spec.md`. **This ledger cites the PR and stops.**

- **Ceiling ~22KB.** Past it the file cannot be read whole, and **a file that cannot be read whole cannot be safely edited.** ⚠️ **08-03: this was called "physics" and it is not.** `maw-agents/uritp-docs` J5 measured 30.6KB reading whole and 34.9KB clipping; the range between is uncharacterised. It is a BUDGET. Do not quote physics without a measurement.
- **Target ~16KB** = floor + real headroom; it replaced a ~12KB target never once met (Floor Rule, `brain-config/hooks/source-size-budget-enforcer.md`).
- **Never split the table** — trim prose. Seat Size Sally before this grows.
- 🔴 **EVERY EDIT THAT ADDS MUST ALSO TRIM, IN THE SAME COMMIT, AND READ THE SIZE BACK.** Six instances; the last two were shipped by sessions that had just read this bullet. **Growth is always prose, never rows, and intending to trim is not trimming.** ⭐ **08-03: the trim that finally worked was STRUCTURAL** — the changelog's own header says findings belong in PR descriptions, and every entry carried one anyway, so the file was breaking its own rule in the section that states it. **Look for a rule the file is already violating before you squeeze a paragraph.**

## Procedure (MANDATORY on every app PR)

1. **Before touching, editing, PR-ing, or even DISCUSSING an app:** read this file. Compare against the version you *think* is current.
2. **Mismatch = STOP.** Re-read at an immutable commit-SHA path or the git blob API (base64-decoded) — never a branch raw URL, which serves copies many versions stale and flattens HTML/SVG out of template literals. Reconcile before building.
3. **Immediately after opening a PR:** update that app's row in the same session. The ledger must never lag `main`.
4. Advisory-blocking on discussion, hard-blocking on edits.

⚠️ **The gate cuts BOTH ways — this file is a CLAIM about reality, not reality. HEAD wins; this file gets corrected.** Four measured rot classes: a **WARNING** (07-25, a "restore pending" note 32 PRs stale, nearly triggering a destructive revert) · an **OPEN-ITEM** (07-28 — *a done job in an open list is an instruction to redo it*) · a **CLASSIFICATION** (07-30) · and a **STRUCTURAL CLAIM** (08-02 "the worker is two files" when it was six; 08-03 a file size asserted under a split line it had crossed) — **the worst class, because it reads as architecture rather than as state.** **Verify before acting on any ⚠️.**

🔴 **A ROW GOES STALE BY DEFAULT, NOT BY ACCIDENT — SIX MEASUREMENTS IN FOUR DAYS.** `inciardi-collection` v3-vs-v16 (07-31), `f1-racetracks` eight versions behind (08-01), `inciardi-collection` four behind *again* 24 hours after a hand correction (08-02), `prism` at v1 against a documented v2.2 (08-03), `git-grab` size claim false within one day (08-03).

> ⭐ **"Try harder at step 3" is retired as a remedy.** Step 3 fires at the END of work, when the thing you came to do is already done, so it has the least momentum behind it. **Step 1 is the enforcement mechanism — read the ledger on the way IN and the gap is unmissable.** Every gap above was caught by step 1; none by step 3.

**Data-separated apps carry TWO version facts:** the *shell* build and the *data* date. A data refresh does NOT bump the shell.

**Version-stamp convention:** carry a version the app itself declares (`APP_VERSION`, or the `?v=` cache-bust) — **not a PR number, not the word "live."** ⚠️ **When an app declares its version in more than one place, say WHICH ONE this row quotes and name the others as disagreeing.** ⚠️ **Never write a version — or a byte count — you have not READ BACK at HEAD.**
