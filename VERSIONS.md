# App Ledger — THE single source of truth for every app

**One file. One row per app. Every folder in the repo root appears here or in the not-apps line.** `brain-config/app-index.md` is retired to a stub; there is no second index.

**Also the tiebreaker against stale reads and CDN lag.** When your read disagrees with this file, **re-read at HEAD and reconcile** — the gate cuts both ways (below).

## 📏 Size (target **~16KB**, ceiling **22KB** — LOCKED 2026-07-26, Michael)

**Each row is CURRENT STATE, not version history.** Per-version narrative lives in git history + the PR description + that app's own `README.md`/`next-build-spec.md`. This ledger cites the PR and stops.

- **Ceiling ~22KB** is physics: base64 inflation past the ~30KB read cap. Past it the file cannot be read whole, and **a file that cannot be read whole cannot be safely edited.**
- **Target ~16KB** = floor + real headroom. It replaced a ~12KB target that had **never once been met** — see the Floor Rule in `brain-config/hooks/source-size-budget-enforcer.md`.
- **Never split the table** — trim prose. Seat Size Sally before this grows.
- ⚠️ **Every edit that adds must also trim**, and **read the resulting size back**. On 2026-08-02 the inciardi correction shipped at **24,140 B — past the ceiling, in the same commit that added a warning about structural rot.** Trimmed in the next commit. **Fifth instance of a capped file being grown by the fix; the growth is always prose, never rows.**

## Procedure (MANDATORY on every app PR)

1. **Before touching, editing, PR-ing, or even DISCUSSING an app:** read this file. Compare against the version you *think* is current.
2. **Mismatch = STOP.** Re-read at an immutable commit-SHA path or the git blob API (base64-decoded). Reconcile before building.
3. **Immediately after opening a PR:** update that app's row in the same session. The ledger must never lag `main`.
4. Advisory-blocking on discussion, hard-blocking on edits.

⚠️ **The gate cuts BOTH ways — this file is a CLAIM about reality, not reality. HEAD wins; this file gets corrected.** A warning rots exactly like a version number (07-25: an `app-dashboard` "restore pending" note was **32 PRs stale** and nearly triggered a destructive revert). So does an **OPEN-ITEMS** entry, more dangerously — **a completed job left in an open-items list is an instruction to redo it** (07-28: an `f1-racetracks` backfill listed as open for five days; redoing it would have overwritten objects with strings). So does a **CLASSIFICATION** (07-30: `inciardi-collection` called "probably a data/spec folder" for four days while live on a phone). **Verify before acting on any ⚠️.**

⚠️ **AND SO DOES A STRUCTURAL CLAIM — the newest class** (2026-08-02). This file said `inciardi-collection`'s worker was **two files** while it was **six**, and hung a *"split before adding any route"* instruction on it: a remediation aimed at a split that had already happened twice. **A structural claim is worse than a stale version, because it reads as architecture rather than as state.**

🔴 **A ROW GOES STALE BY DEFAULT, NOT BY ACCIDENT — FOUR MEASUREMENTS IN 72 HOURS.** 07-31: `inciardi-collection` said **v3** against `main` on **v16**, was corrected to v17, then **v18 and v19 shipped without touching it again.** 08-01: `f1-racetracks` was **eight versions and ten PRs behind**. 08-02: `inciardi-collection` was **four behind AGAIN** (v19 vs v23) — *the same row, hand-corrected the previous day, stale inside 24 hours.*

> ⭐ **"Try harder at step 3" is retired as a remedy. Step 3 fires at the END of work, when the thing you came to do is already done, so it has the least momentum behind it. Step 1 is the enforcement mechanism — read the ledger on the way IN and the gap is unmissable.** All four gaps above were caught by step 1; none by step 3.

**Data-separated apps carry TWO version facts:** the *shell* build and the *data* date. A data refresh does NOT bump the shell.

**Version-stamp convention:** carry a version the app itself declares (`APP_VERSION`, or the `?v=` cache-bust) — **not a PR number, not the word "live."** ⚠️ **When an app declares its version in more than one place, say WHICH ONE this row quotes and name the others as disagreeing.** ⚠️ **Never write a version you have not READ BACK at HEAD** — an estimated version is the same defect as an estimated byte count.

**⚠️ Read-path note (verified 2026-07-25):** branch raw URLs served copies MANY versions stale AND flatten HTML/SVG out of template literals. Reliable: blob API base64-decoded, or `get_file_contents` at an immutable commit SHA.

## Coverage rule

**Every folder in the repo root is either in the table above or in the not-apps line. Nothing gets to be invisible.** Four apps were found in the root tree on 2026-07-25 in NEITHER former index, and a fifth (`inciardi-collection`) on 07-26 missing from this ledger itself. **An app nobody indexes is an app nobody verifies.**

⚠️ **Coverage proves an app is LISTED, never that it is still NEEDED.** `routines` was correctly indexed, freshly versioned and actively maintained on the day it was deleted as redundant. **Every duplicate-check we own runs at creation time; none re-run when the world changes.**

⚠️ **Nor does coverage prove a row is TRUE or CURRENT.** Both actively-developed apps here have now been found multiple versions stale within days of being hand-corrected. **A maintained row is not a verified row** — stamp what you checked and when.
