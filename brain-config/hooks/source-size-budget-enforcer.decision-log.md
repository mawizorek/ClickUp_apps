## Why this was wrong, not just misplaced

The Decision Logs Gold Standard is **ClickUp-native by construction**, and its core mechanic proves it: **inverted checkbox polarity.** Michael answers a `Q` block by CHECKING the options he *rejects*, which renders them struck-through. That requires a clickable checkbox.

In a repo markdown file, `- [ ]` is inert text. The `Q1` block originally written here **could not have been answered** without hand-editing a file through the GitHub UI. An interactive artifact was shipped into a non-interactive surface.

The same applies to the rest of the format: banner callouts, nested subpages under the item they document, and the pointer-line convention are all ClickUp constructs.

## The trap that caused it

This file was named by copying an adjacent repo file (`session-close.decision-log.md`) instead of following the governing standard. The Gold Standard predicts exactly this in its own enforcement section:

> *"A consistent log teaches its own format... one riffed entry is a real cost — it pollutes the exemplar and invites the next agent to riff too."*

The repo-resident decision logs are that polluted exemplar. **If you are about to create a decision log because you saw one in this folder: don't.** Load the Gold Standard and create a ClickUp page.
