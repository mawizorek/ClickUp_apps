## Durable patterns

- A note claiming work is pending after it shipped is stronger than a simple stale note; inherited TODOs survive because nobody doubts them. Fire the doc-rot check.
- A repeated deviation is a spec gap, not an apology.
- Empty output is not proof of clean state. An unused gate and a broken gate look identical externally.
- Files can grow beyond readability while size gates remain unfired. Measure at write time and rotate before cap.
- Stale references need blob-first reload immediately before writes.
- Completeness and placement are different transcript failures.
- Two claimants on one truth drift; collapse the mirror rather than add another.
- Retirement pointers need a sweep aimed at the retired target.
- Capacity and discipline-ordering can degrade independently; early sequencing gates matter.
- Recall, restraint, and calibration are separate axes. A session can keep perfect recall and still fail by not stopping, or by asserting from inference.
- Structural doc inserts can silently eat an adjacent heading and hide an open question inside the block above. After any structural insert, look at the neighbours.
- A document about a data store is always closer to hand than the store, and a project's own planning docs are not exempt. Open the store first.
- "Nothing depends on this" needs more containers opened than "this doesn't exist," and is the claim nobody checks.
- A pointer copied into a faster-read surface beats its own source, because the copy is read first. Point at the surface, never restate its internals.
