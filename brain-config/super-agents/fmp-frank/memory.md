## 🚩 THE DERIVED-DATA LAW (EARNED 08-08 — five instances in one session)

**A flag whose meaning is "this row is not real" is the schema telling you the row should not exist.**
Legacy `autoGenerated = 1` marked duplicated event rows so the rest of the system could distrust them;
that flag then leaked into a print script's sort order. Same species, four more times the same day:
convenience-copy dates on two tables, second-claimant highlight fields, a `ManualEdit` flag I proposed
myself, and a rival README I nearly merged beside a file that already existed.

- **The test:** if a value can be recomputed, it is a PROJECTION. A projection is never edited, never
  flagged, never preserved across a rebuild — **delete and regenerate, unconditionally.** The moment it
  holds one hand-edit it is a second source of truth in a temporary costume.
- **Three layers, and this generalizes past FileMaker:** CANONICAL (typed, holds identity) ·
  PROJECTION (generated, disposable) · ARCHIVE (append-only, never trashed). Placing a table is asking
  which of the three it is.
- 🔴 **I can name this pattern and still commit it.** Instance five was mine, ninety minutes after I
  wrote the rule down. **Before creating any file, read the directory it lands in.**

## 🔗 FMP ↔ repo correlations (the shared vocabulary — the point of me)

Shape: **FMP construct → repo equivalent → where it holds → where it BREAKS.** The breaks half matters
most; a correlation with no stated limit is a slogan.

- 🔴 **C1 · Object family → repo component token set.** Both exist to stop one job being solved three
  ways, so it **holds** at intent. **Breaks at STATE:** FMP fakes state with stacked objects + hide
  conditions (one object per state); CSS uses a class on ONE element. Many-state families are cheap in
  the repo, expensive in FMP — **never let repo state-richness set the FMP family count.**
- 🔴 **C2 · Table view → rendering straight off the data.** FMP table view renders the schema itself;
  the repo analogue renders off the JSON with no view model between. **Holds** as the argument that good
  field/key naming IS the UI in both runtimes. **Breaks** on parent-with-children: table view flatly
  cannot, and a portal (or nested render) is the answer.
- 🔴 **C3 · Portal row → the list-item component, the CHEAPEST layout in either runtime.** One object
  set renders N records, so styling is paid once and amortized. **Breaks on editability:** an FMP portal
  is an editing surface *by default*, a repo list render is read-only by default. **Never assume a safe
  default transfers across runtimes.**
- 🔴 **C4 · Multi-predicate RANGE relationship → a filter/predicate over a collection** (EARNED 08-08).
  An FMP relationship can carry inequalities (`date >= start`, `date <= end`) plus a sort, which is how
  one row is seen by every day it spans and how N overlapping rows resolve to one winner. **Holds** as
  the general answer to "a record applies to a RANGE, not a key." **Breaks on indexing** — inequality
  predicates cannot use a stored index, so it is a small-set tool; and **breaks on repetition**: a
  relationship feeds a fixed-height PORTAL, and a LIST VIEW repeats per RECORD, so a range join cannot
  make one row render as three rows. That second break is why a generated projection table exists.
- 🔴 **C5 · Generated projection table → a computed/derived view** (EARNED 08-08). Rebuilt from
  canonical data at a known trigger, never edited, never the source of truth. **Holds** as the escape
  from expensive live resolution AND as the only way to get per-instance report rows. **Breaks on
  lineage:** re-rendering an old output renders TODAY's data, so a projection can never be an archive.
  ⚠️ **Build it at IMPORT, never at PRINT** — printing must not be a write, or a read-only report
  cannot run on a locked file or run twice safely.
- 🔴 **C6 · Auto-enter "do not replace" → a value frozen at creation** (EARNED 08-08). A plain
  calculation recomputes, which silently rewrites history the first time the formula is touched; the
  same trap is unstored calcs on imported timestamps. **Holds** anywhere a stored value must mean "what
  was true when this row was written." **The repo equivalent is a written-once field, and neither
  runtime warns you** when you pick the recomputing version.
