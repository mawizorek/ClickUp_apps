## 🎬 SCRIPT KNOWLEDGE — the demand ledger (born 2026-08-10, session `86ajyw19j`)

🌟 **A PM's script breakdown is NOT the character/scene grid and NOT a cue book. It is three layers, and fusing them is what makes every homemade version laborious and revision-fragile:**

1. **SPINE** — French-scene units. Thin, boring, a JOIN KEY. Nobody reads a key and nobody WORKS a unit (no assignees, no dates — the moment a unit is assigned it stopped being a spine).
2. **DEMANDS** — one row per obligation the script creates, typed Money · Hazard · People · Time · Rights. The actual instrument.
3. **EVIDENCE** — page clip and annotation, attached to a DEMAND, never floating on a canvas.

- 🎯 **The boundary that keeps it from becoming a cue book: a row exists if and only if the script OBLIGATES A RESOURCE.** No themes, no beats, no intentions, no directorial reading. Interpretation gets no column because it gets no table.
- 🔴 **A DEMAND IS A REQUIREMENT; A DESIGN ELEMENT IS A SOLUTION. They link, they never merge.** Proven on Big Love: **9 of 9 Show Design elements have ZERO script origin** (they come from the room — risers, exit signs, PSM camera), and **6 of 10 sampled demands can never be one** (intimacy protocol, fight call, dances, dialect, two song clearances). Two rows describing one bathtub diverge, and then nobody knows which one the designer read.
- 🔴 **`waived` is the status a Design Element structurally cannot have.** A design never gets waived, it quietly never gets made and later nobody can tell whether that was a decision or a miss. A demand must be able to say *"the script asks for 300 wine glasses, we saw it, we are not doing it."* **That stack of waivers IS the document you hand the director.** Demand lifecycle: `raised → confirmed → covered → satisfied / waived / cut`.
- ⚠️ **A unit boundary is a personnel change OR A STAGE-PICTURE CHANGE.** Personnel alone is insufficient — a four-minute wordless dance with the company frozen and a monologue can have identical bodies on stage and are different production events.
- **Production-wide demands need a `U00 · PRODUCTION` pseudo-unit.** An empty relationship reads as an error; a deliberate row reads as a decision.
- ✅ **A ClickUp List Relationship holds MULTIPLE targets**, so one demand spans many units (the bathtub is on stage all play) with no duplicate rows. **One relationship field, not one per unit.**
- ⚠️ **Sequential IDs require sequential reading.** Break the pass out of page order and every downstream ID is provisional.
- 📏 **Grain, measured not guessed:** Mee's *Big Love* ran **14 French-scene units and 31 demands across 60 pages** → ~28 units / ~65 demands for a full script. **Both my first estimates (40-70 units, 150-300 demands) were 2-4× too high.** A per-LINE record is a different animal: ~35 lines/page → **~4,000 rows, which is not a ClickUp shape.**
- 🌟 **THE DIFF IS THE KILLER USE, NOT THE ANNOTATION.** A line-level table framed as "a director's per-line notes" costs 4,000 rows and is a nice-to-have. Framed as `Version` + `State` (present/cut/added/altered) it answers *"what changed?"* as a QUERY instead of a re-read — **and capturing only `Line Type = Stage direction` cuts it to ~400 rows, which is the same subset that carries every production demand in a Mee play and the same subset a director actually edits.**
- 🔴 **IN A MEE PLAY THE STAGE DIRECTIONS ARE THE BUDGET.** The bathtub, 100 olive trees, 300 wine glasses, the smashed crockery, the splatted tomatoes, both long dances — all stage direction. **A director trimming "unnecessary stage directions" is editing the cost of the show without knowing it.** The cost view is therefore an INPUT to his cut, not a report after it.
- **Consumables are invisible on a props list and obvious on a demand ledger:** breakable crockery and ~8 tomatoes PER PERFORMANCE. **Restock × run length is a real budget line nobody prices.**
- **Sequencing hazards are only visible when the units are IN ORDER** — glass shattered in one unit and a barefoot dance on the same deck three units later is a finding no single-axis list produces.
