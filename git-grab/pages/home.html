Grab a folder

Paste a link to any folder on GitHub. Get back a .zip of that folder and everything inside it.

Pick a folder

Saved locations are just shortcuts. Picking one fills the box below; nothing is fetched until you ask for it.

Open the folder on GitHub and copy the address bar. A /tree/ link, a /blob/ link to a single file, or a permalink with a long commit hash all work. Public repositories only — private repos need a token, which comes later.

What happens next

Nothing downloads straight away. First you get a list of exactly what is about to be packed, with a file count and a total size, so you can see the whole thing before committing to it. Then one button turns it into a zip, in your browser — the files never touch anyone else's server.

The file count is the point of this screen. A download is only correct when the number here matches the number of files in the zip and the number GitHub reports — and if anything is deliberately left out (submodules and symlinks cannot be packed, because there is no actual file to fetch), it gets named here rather than quietly dropped. A zip that is silently missing four files is worse than no zip at all.

Every request goes to github.com and nowhere else, and that is enforced in code rather than promised in a README.
