Self test

Checks the zip writer against itself, then hands you a real archive to open.

Two different kinds of proof, and only one of them happens here. The checks below build a zip in memory and read it back, which proves the writer is internally consistent. It does not prove your computer can open the file — nothing running in a browser tab can prove that. Download the sample at the end and double-click it. That is the real test.

What it packs

readme.txt
plain text, short
nested/deep/data.txt
long and repetitive — deflate must shrink it
unicode/café — ✅.txt
non-ASCII filename, proves the UTF-8 flag
empty.txt
zero bytes, the classic off-by-one

Nested paths are deliberate: this writer does not emit directory entries, it relies on the slashes in a path implying folders. If nested/deep/ comes out flat, that assumption was wrong and the pipeline should not be built on top of it.
