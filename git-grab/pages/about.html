About git-grab

GitHub will hand you a whole repository as a zip, but not a single folder inside one. git-grab does the folder.

Why not just use download-directory.github.io

You can, and it works. The reason this exists is narrower than distrust of its author: the code is open and almost certainly fine today, but auditing a site you do not control only binds the deploy you audited. A dependency bump next week is not something you get to re-read. This app sits on an origin Michael controls, so the audit stays true until he changes it.

What it touches, and what it refuses to

Two hostnames, enforced by a wrapper rather than by good intentions: api.github.com to resolve the ref and list the tree, and raw.githubusercontent.com to fetch file bodies. Any other host throws. Zipping happens in your browser with the native CompressionStream API, so there is no third-party script to trust at runtime and nothing to keep patched.

Public repos only

There is no token field, deliberately. A private-repo gate is designed but not built; when it lands, the token is held in memory by default and only ever sent to api.github.com.

Note on the error messages you may eventually see: GitHub returns 404, not 403, for a private repo you are not authenticated for. It deliberately refuses to confirm the repo exists at all. So a failure here can never honestly say "this one is private" — only that the path could not be reached.

Everything is pinned

Whatever ref you paste is resolved to a commit SHA once, and every request after that uses the SHA. Two people pasting the same permalink get byte-identical zips, and a branch moving under you mid-download cannot happen.
